# 项目进度记录设计

最后更新：2026-07-04

## 1. 目标

新增 `docs/progress.md` 作为项目完成进度的唯一权威记录，让开发者无需翻阅提交、
计划和多份说明文档，就能确认当前完成度、验证证据、剩余工作和最后更新时间。

该文件记录产品范围覆盖情况，不替代需求、架构、API、测试或变更记录。

## 2. 记录结构

文件由四部分组成：

1. 当前阶段：记录正在推进的阶段、当前功能分支和下一步。
2. 整体进度：按一级产品模块等权计算范围覆盖率，明确该百分比不是工时或工期预测。
3. 模块进度主表：统一记录模块、完成度、状态、验证结果、待办和更新时间。
4. 阶段记录：按时间倒序保存已经完成的重要阶段、提交和验证证据。

## 3. 状态与完成度口径

状态只能使用以下四种值：

- `已完成`：验收标准已满足，自动化验证通过。
- `进行中`：已有实现，但阶段验收尚未全部满足。
- `待开发`：已确认范围，尚未开始实现。
- `受阻`：存在无法在当前权限或环境内解决的明确阻塞。

完成度使用 `0%`、`25%`、`50%`、`75%`、`100%` 五档，避免没有依据的精细数字：

- `0%`：未开始。
- `25%`：需求和设计完成。
- `50%`：核心后端或核心业务逻辑完成。
- `75%`：三端主要交互完成，仍缺验收或加固。
- `100%`：当前阶段验收和验证全部通过。

整体进度按主表内一级模块完成度的算术平均值计算，并在文件中声明该计算方式。

## 4. 主表字段

| 字段 | 规则 |
| --- | --- |
| 模块 | 使用稳定的一级业务模块名称 |
| 完成度 | 使用五档百分比 |
| 状态 | 使用统一四状态之一 |
| 验证结果 | 写测试数量、构建、HTTP 或浏览器验证；没有验证写“尚未验证” |
| 待办 | 只写达到下一完成档位所需的关键工作 |
| 更新时间 | 使用 `YYYY-MM-DD HH:mm`，时区为 Asia/Shanghai |

首版主表覆盖：工程基础、商品目录、本地素材、管理员认证、DIY 设计、方案保存、
规则推荐、库存、订单与模拟支付、履约与 BOM、第三方能力替换。

## 6. 维护规则

- 每完成一个可验收阶段，同步更新主表和阶段记录。
- 每次只保留当前有效完成度，不在主表堆叠历史状态。
- 阶段记录只保存重要里程碑，不记录每次小修改。
- 验证结果必须来自实际执行，不使用“预计通过”或“应该正常”。
- `docs/overview.md` 和根 `README.md` 只保留进度表入口，不复制完整进度数据。
- 需求范围变化时，先更新 `docs/requirements.md`，再调整进度模块和整体完成度。
