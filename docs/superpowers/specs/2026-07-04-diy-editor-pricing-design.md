# DIY 编辑器、权威计价与方案草稿设计规格

最后更新：2026-07-04  
状态：已确认，等待实施计划  
适用项目：DIY 手串定制商城  
前置里程碑：商品目录纵向链路已完成并合并

## 1. 目标

本阶段交付一个可实际使用的 DIY 设计闭环：

> 匿名访客进入小程序 → 配置腕围和松紧程度 → 选择并排列珠子 → 查看实时预估 →
> 获取后端权威报价 → 保存、恢复、复制或删除方案 → 生成并保存 Canvas 预览图

同时在 Vue 管理后台提供 DIY 尺寸规则、工艺费和绳材费用的配置能力。
微信授权、对象存储和支付仍通过明确接口隔离，本阶段分别使用访客身份、本地文件存储，
且不接入支付。

## 2. 已确认的关键决策

1. 采用完整纵向闭环，不采用仅保存在小程序本地的临时方案。
2. 未接入微信授权前，小程序通过匿名访客身份适配器获得签名令牌。
3. 腕围范围、松紧余量、允许误差和最大珠数均由管理后台配置。
4. 默认松紧规则为贴合增加 5 mm、标准增加 10 mm、宽松增加 15 mm；
   默认允许误差为 ±4 mm，默认腕围范围为 120–250 mm。
5. 权威总价由珠子金额、按珠数区间配置的工艺费和绳材附加费组成。
6. 方案只保存有序 SKU ID 数组，不为每颗珠子创建业务 ID 或数据库记录。
7. 前端按数组位置临时生成展示序号，并按 SKU ID 分组统计数量和计算价格。
8. 小程序采用“Canvas 工作台”布局，不采用强制分步向导。
9. 尺寸或珠数不合格的设计允许保存草稿，但不能确认权威报价或进入后续下单。
10. 预算、色系、材质和场景规则推荐不属于本阶段，作为下一阶段独立实施。

## 3. 范围

### 3.1 本阶段包含

- 匿名访客会话和访客数据隔离；
- DIY 配置、工艺费区间和绳材选项；
- 从空白或现有套餐开始设计；
- 珠子的添加、删除、替换、拖动排序、清空、撤销和重做；
- 腕围、松紧档位、当前长度、目标长度和尺寸状态；
- 客户端实时预估和服务端权威报价；
- 方案新建、命名、保存、恢复、复制、软删除和并发版本控制；
- Canvas 预览图导出、上传、绑定和失败重试；
- 管理后台配置页面；
- 后端、管理后台和小程序的自动化验证；
- API、数据模型、开发说明、项目总览、变更记录和进度表更新。

### 3.2 本阶段不包含

- 微信登录、手机号授权或账号合并界面；
- 规则推荐或 AI 推荐；
- 库存预占和缺货订阅；
- 订单、收货地址、模拟支付、生产 BOM 和履约；

## 4. 总体架构

### 4.1 后端模块

#### `identity`

定义 `CustomerIdentityResolver`，把 HTTP 请求解析为稳定的顾客身份。当前实现接收签名访客
JWT；未来微信适配器可把 OpenID 映射到相同顾客主键，不改变 DIY 应用服务。

访客首次启动时提交本机安装 UUID。后端不把原始 UUID 当作授权凭据，而是创建或查找访客
身份并签发带顾客主键、令牌类型和过期时间的 JWT。管理 JWT 与顾客 JWT 使用不同的类型声明，
防止两个认证域混用。

#### `diy`

负责方案生命周期、方案所有权、SKU 顺序数组、软删除、复制、预览素材绑定和乐观锁。
Controller 只处理请求契约；应用服务处理所有权和事务；Mapper 只处理 SQL。

#### `pricing`

负责尺寸校验、SKU 有效性、SKU 数量统计、工艺费匹配、绳材校验和金额汇总。
服务端每次权威报价都重新读取当前有效数据，绝不采用客户端上传的单价或总价。

#### `configuration`

负责 DIY 尺寸规则、工艺费区间和绳材选项。保存配置时在一个事务内校验完整性并增加配置版本。

#### `file`

复用现有 `FileStorage` 端口保存 Canvas 预览图。当前由 `LocalFileStorage` 实现；
后续切换对象存储时不修改 DIY 模块。

### 4.2 小程序模块

- `editor-state.ts`：纯 TypeScript 编辑状态与命令；
- `editor-history.ts`：最多 50 步撤销和重做；
- `bracelet-layout.ts`：根据顺序、珠径和画布大小计算环形坐标；
- `price-estimate.ts`：仅用于交互反馈的整数分预估；
- `diy-session.ts`：访客会话建立、续期和令牌保存；
- `diy.ts`：配置、报价和方案接口；
- Canvas 页面：渲染、触摸命中和拖动反馈，不承载业务规则；
- 方案页面：列表、恢复、复制、删除和预览失败重试；
- 本地恢复缓存：保存未提交的当前编辑状态。

### 4.3 管理后台模块

- “DIY 规则”页面：腕围范围、三档余量、允许误差、最大珠数；
- “计价规则”页面：工艺费区间和绳材选项；
- 所有表单使用既有管理 JWT 和统一 HTTP 客户端；
- 保存前进行前端即时校验，后端再次执行完整校验。

## 5. 编辑器状态模型

### 5.1 SKU 顺序

方案使用一个有序 SKU ID 数组：

```json
{
  "sequence": [101, 101, 202, 101, 303, 101, 404, 101, 505, 101, 101, 505]
}
```

数组下标决定排列顺序。Canvas 展示时生成从 1 开始的临时序号，不保存单颗珠子 ID。
计价和后续 BOM 使用分组统计：

```json
{
  "101": 7,
  "202": 1,
  "303": 1,
  "404": 1,
  "505": 2
}
```

顺序数组是唯一事实来源，数量映射由前后端按需派生，避免顺序和数量两份数据不一致。

### 5.2 编辑操作

- 添加：在当前选中位置之后插入 SKU ID；无选中项时追加；
- 删除：按当前位置移除一个 SKU ID；
- 替换：只替换当前位置的 SKU ID；
- 拖动：把一个数组元素移动到目标下标；
- 清空：把数组替换为空数组；
- 套餐初始化：按套餐明细顺序和数量展开成 SKU ID 数组；
- 撤销/重做：保存纯状态快照，最多 50 步，不上传到后端；
- SKU 数量快捷调整：增加时在最后一个同 SKU 位置后插入，减少时删除最后一个同 SKU；
- 服务端保存：校验数组元素均为正整数，技术上限为 200 项。

管理后台不提供单颗珠子维护；珠子品种继续由商品目录中的 `bead_sku` 管理。

## 6. 尺寸规则

### 6.1 计算

```text
目标长度 = 腕围 + 当前松紧档位余量
当前长度 = 顺序数组中各 SKU 珠径之和
偏差 = 当前长度 - 目标长度
```

当偏差绝对值不大于允许误差时，尺寸状态为 `FIT`。偏差小于负误差时为 `TOO_SHORT`，
大于正误差时为 `TOO_LONG`。

### 6.2 默认配置

| 配置 | 默认值 |
| --- | ---: |
| 最小腕围 | 120 mm |
| 最大腕围 | 250 mm |
| 贴合余量 | 5 mm |
| 标准余量 | 10 mm |
| 宽松余量 | 15 mm |
| 允许误差 | 4 mm |
| 最大珠数 | 60 |

以上全部由管理后台维护。配置必须满足：

- 最小腕围大于 0 且小于最大腕围；
- 三档余量均为非负数；
- 允许误差为非负数；
- 最大珠数在 1–200 之间；
- 每次成功保存后配置版本递增。

草稿允许为空、尺寸不合格或超过业务最大珠数，但技术上限、数据类型和请求体大小仍必须满足。
权威报价要求方案非空、腕围处于配置范围、珠数不超过业务最大值且尺寸为 `FIT`。

## 7. 计价规则

### 7.1 公式

```text
珠子金额 = Σ（当前有效 SKU 售价 × 该 SKU 出现次数）
权威总价 = 珠子金额 + 工艺费 + 绳材附加费
```

后端使用 `BigDecimal` 和两位小数，前端预估统一转换为整数分运算。
客户端只上传 SKU ID、顺序、腕围、松紧档位和绳材 ID，不上传可信单价。

### 7.2 工艺费

每条规则包含最小珠数、最大珠数、固定费用、启用状态和排序值。
启用规则必须从 1 连续覆盖当前最大珠数，不能重叠或留空档。

初始演示配置为 `1–60 颗：10.00 元`，管理员可立即调整或拆分区间。
保存工艺费规则时整体替换并在事务中验证，避免短暂出现重叠或缺口。

### 7.3 绳材

每个绳材选项包含稳定编码、名称、展示颜色、附加费、状态和排序值。
初始提供透明、黑色和棕色弹力绳，附加费均为 `0.00`，管理员可修改。

### 7.4 报价指纹

权威报价返回 `quoteFingerprint`，由规范化后的 SKU 与数量、当前 SKU 价格、
尺寸配置版本、命中的工艺费规则版本和绳材版本共同计算。

方案保存最近一次报价和指纹用于展示，但下单阶段必须再次权威计价。
价格、状态或规则改变后，旧指纹不再有效，方案标记为 `STALE` 并提示重新报价。

## 8. 数据模型

### 8.1 `customer_identity`

| 字段 | 说明 |
| --- | --- |
| `id` | 顾客身份主键 |
| `source` | `GUEST`，后续可增加 `WECHAT` |
| `external_key_hash` | 安装 UUID 的服务端摘要，唯一 |
| `status` | `ACTIVE`、`DISABLED` |
| `created_at/updated_at` | 审计时间 |

不保存可直接用作授权凭据的原始安装 UUID。

### 8.2 `diy_rule_config`

单例配置，包含腕围上下限、三档余量、允许误差、最大珠数、配置版本和审计时间。

### 8.3 `craft_fee_rule`

包含珠数上下限、固定费用、状态、排序、规则版本和审计时间。

### 8.4 `cord_option`

包含稳定编码、名称、颜色值、附加费、状态、排序、版本和审计时间。

### 8.5 `diy_scheme`

| 字段 | 说明 |
| --- | --- |
| `id` | 方案主键 |
| `customer_identity_id` | 所属访客或顾客 |
| `name` | 1–80 字符的方案名称 |
| `wrist_circumference_mm` | 腕围，毫米 |
| `fit_type` | `SNUG`、`STANDARD`、`LOOSE` |
| `cord_option_id` | 选中的绳材 |
| `sequence_json` | 有序 SKU ID JSON 数组 |
| `bead_count` | 派生珠数，便于列表展示 |
| `catalog_snapshot_json` | 最近保存时的 SKU 名称、珠径和封面展示快照 |
| `bead_amount/craft_fee/cord_fee/total_amount` | 最近一次有效报价，可空 |
| `quote_fingerprint` | 最近报价指纹，可空 |
| `quote_status` | `NOT_QUOTED`、`VALID`、`STALE`、`INVALID` |
| `preview_asset_id` | Canvas 预览素材，可空 |
| `status` | `ACTIVE`、`DELETED` |
| `version` | 乐观锁版本 |
| `created_at/updated_at` | 审计时间 |

`catalog_snapshot_json` 只用于在 SKU 下架后恢复画面和提示，不能参与权威计价。
商品目录继续采用状态下架，不在正常管理流程中物理删除已发布 SKU。

## 9. HTTP 接口

### 9.1 访客会话

```http
POST /api/app/session/guest
Content-Type: application/json

{"installationId":"3f6f7816-0f1a-4aa0-870f-f34f9195a2ec"}
```

返回顾客访问令牌、有效秒数和顾客身份主键。令牌默认有效 30 天；
小程序在临近过期或首次收到 401 时只自动续期一次。

### 9.2 DIY 配置

```http
GET /api/app/diy/config
Authorization: Bearer <customer-token>
```

返回尺寸规则、可用绳材、配置版本和计价说明。商品列表继续复用公共目录接口。

### 9.3 权威报价

```http
POST /api/app/diy/quotes
Authorization: Bearer <customer-token>
Content-Type: application/json

{
  "wristCircumferenceMm": 160,
  "fitType": "STANDARD",
  "cordOptionId": 1,
  "sequence": [101, 101, 202, 101]
}
```

返回：

- SKU 数量明细；
- 当前长度、目标长度、偏差和尺寸状态；
- 珠子金额、工艺费、绳材费用和总价；
- 配置版本和报价指纹；
- 可恢复的稳定错误明细。

### 9.4 方案

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/app/diy/schemes` | 新建方案 |
| `GET` | `/api/app/diy/schemes` | 当前顾客方案列表 |
| `GET` | `/api/app/diy/schemes/{id}` | 读取并恢复方案 |
| `PUT` | `/api/app/diy/schemes/{id}` | 携带版本号更新方案 |
| `POST` | `/api/app/diy/schemes/{id}/copies` | 复制方案 |
| `DELETE` | `/api/app/diy/schemes/{id}` | 软删除方案 |
| `POST` | `/api/app/diy/schemes/{id}/preview` | 上传并绑定预览图 |

所有按 ID 操作都必须同时检查 `customer_identity_id`，不存在和不属于当前顾客统一返回资源不存在，
避免泄漏其他顾客是否拥有该方案。

### 9.5 管理接口

- `GET/PUT /api/admin/diy/config`；
- `GET/PUT /api/admin/diy/craft-fees`；
- `GET/POST/PUT /api/admin/diy/cord-options`；
- `PUT /api/admin/diy/cord-options/{id}/status`。

管理配置写入继续使用既有管理 JWT、稳定错误响应和审计时间。

## 10. 小程序界面

采用已确认的 A 方案“Canvas 工作台”：

- 顶部显示腕围、松紧档位和绳材；
- 中央大区域显示环形 Canvas、珠数、当前长度、目标状态和撤销/重做；
- 价格以固定信息条显示，明确区分“预估”和“权威报价”；
- 底部素材抽屉按分类显示珠子，支持搜索和数量快捷调整；
- 固定操作区提供“保存草稿”和“确认报价”；
- 点击 Canvas 珠子后显示临时序号、SKU 名称、替换和删除操作；
- 拖动时显示目标插入位置，松手后才提交状态；
- 首次进入提供可跳过的简短操作引导，不使用强制分步流程；
- 方案列表显示名称、预览、珠数、金额、报价状态和更新时间。

视觉原型由本地可视化设计会话生成，运行目录 `.superpowers/` 不进入 Git。
正式实现沿用当前小程序的视觉语言，并根据真实设备尺寸进行适配。

## 11. 数据流

### 11.1 启动和编辑

1. 小程序读取或生成安装 UUID；
2. 交换或刷新访客 JWT；
3. 并行加载 DIY 配置、分类和已上架 SKU；
4. 从空白、套餐、已保存方案或本地恢复缓存创建编辑状态；
5. 每个编辑命令生成新状态并更新撤销栈；
6. Canvas 只根据状态计算坐标和绘制；
7. 前端按整数分计算即时预估并明确标记为预估。

### 11.2 保存

1. 小程序提交业务字段、SKU 顺序数组和当前版本；
2. 后端检查身份、数据结构、技术上限和乐观锁；
3. 后端读取 SKU 生成展示快照和当前报价状态；
4. 后端复用同一个计价器计算当前结果：规则全部满足时保存有效报价，
   不满足时清空旧金额并保存 `INVALID` 或 `STALE` 状态；
5. 在事务内保存方案；
6. 小程序导出 Canvas 图片并调用预览接口；
7. 图片失败时保留方案，并在本地记录待重试任务。

### 11.3 权威报价

1. 后端按顺序数组批量读取所有 SKU；
2. 校验 SKU 存在、已上架且所属分类可售；
3. 分组统计 SKU 数量并计算珠子金额；
4. 计算目标长度和当前长度；
5. 校验腕围、误差、珠数和绳材；
6. 匹配唯一工艺费规则；
7. 返回金额明细、尺寸结果、规则版本和报价指纹。

独立报价接口不写数据库。保存方案时后端会再次运行相同计价器，因此客户端不能通过复用旧指纹
或篡改返回金额把过期报价写入方案。

## 12. 失败策略

| 场景 | 行为 |
| --- | --- |
| SKU 下架或不存在 | 保留原顺序和展示快照，标红并禁止权威报价 |
| 价格或配置变化 | 旧报价变为 `STALE`，提示重新报价 |
| 尺寸不合格或珠数超限 | 允许保存草稿，报价返回明确校验错误 |
| 访客令牌过期 | 自动续期一次，失败后提示用户重试 |
| 方案版本冲突 | 返回 409，不覆盖服务端版本；允许重新载入或复制 |
| 网络中断 | 当前状态写入本地恢复缓存，联网后手动保存 |
| 预览上传失败 | 方案保存成功，标记待生成预览并允许重试 |
| 工艺费规则重叠或有缺口 | 管理保存失败，旧配置保持不变 |
| 文件类型或大小非法 | 复用文件模块稳定错误，不绑定素材 |

## 13. 安全与边界

- 顾客接口和管理接口使用不同令牌类型；
- 服务端不信任客户端金额、数量汇总、尺寸状态或报价状态；
- 安装 UUID 只用于身份交换，数据库保存服务端摘要；
- 方案访问始终同时校验资源 ID 和所有者；
- 所有数组、名称、图片、数字和分页参数均有明确上限；
- 预览图沿用 PNG、JPEG、WebP 和 5 MiB 上限；
- 方案使用软删除，防止误操作导致后续审计信息丢失；
- 报价无数据库写事务依赖；方案写入和版本更新使用本地事务；
- 日志不记录原始令牌、安装 UUID 或完整请求体。
