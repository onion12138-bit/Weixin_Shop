# 微信小程序首页视觉改版设计

## 目标

将微信小程序现有首页改造成用户提供的粉色水晶手串首页样式。页面使用 `Pic/bracelet_homepage_assets_named` 中的独立图片素材，保留小程序原生页面结构和可点击交互，只实现前端能够明确落地的功能。

## 范围

本次只修改原生微信小程序首页及首页使用的静态资源，不修改后端、管理后台、商品数据结构或现有业务页面。

页面需要包含：

1. 粉色水晶手串主视觉区和“AI 灵感咨询”页面标题。
2. “开始 DIY”“AI 情绪推荐”“成品精选”三个主要入口。
3. 四张心情推荐卡和“换一换”交互。
4. 四张成品精选卡。
5. 一张现有方案卡和继续编辑入口。
6. 分享引导卡。
7. 首页、灵感、DIY、我的四项底部导航。

## 视觉实现

- 使用现有主视觉、心情图和成品图，不将整张设计稿作为页面背景。
- 页面以柔粉、白色和深紫色为主，使用大圆角卡片、轻阴影和克制的粉色强调。
- 主视觉图片以裁切方式占据首屏右侧和背景区域，左侧保留标题、说明和三个圆角按钮。
- 主体内容按参考图顺序纵向排列，适配不同宽度的小程序视口。
- 页面底部为固定导航，正文预留安全区和导航高度，避免遮挡内容。
- 使用小程序原生导航栏显示“AI 灵感咨询”，并保留微信胶囊区域。

## 交互与路由

| 首页元素 | 行为 |
| --- | --- |
| 开始 DIY | 跳转 `/pages/diy/editor` |
| AI 情绪推荐 | 跳转 `/pages/recommendation/index` |
| 成品精选按钮、商品卡、查看更多 | 跳转 `/pages/catalog/index` |
| 心情卡 | 在首页切换当前选中状态 |
| 换一换 | 轮换心情卡显示顺序，并更新当前选中项 |
| 我的方案、查看全部 | 跳转 `/pages/diy/schemes` |
| 继续编辑 | 跳转 `/pages/diy/editor` |
| 分享卡 | 调用微信小程序页面分享能力 |
| 底部首页 | 保持当前页并回到页面顶部 |
| 底部灵感 | 跳转 `/pages/recommendation/index` |
| 底部 DIY | 跳转 `/pages/diy/editor` |
| 底部我的 | 跳转 `/pages/diy/schemes`，作为当前项目中最接近“我的”的已有页面 |

商品卡不绑定具体后端商品 ID，因为参考图素材与当前商品数据没有可靠映射。收藏图标只展示视觉状态，不做持久化。

## 组件与状态

首页继续使用 `pages/home/index` 的原生小程序页面文件：

- `index.ts`：维护心情卡、商品卡、导航方法、换一换和分享配置。
- `index.wxml`：按主视觉、心情推荐、成品精选、我的方案、分享和底部导航拆分语义区块。
- `index.wxss`：实现布局、响应式尺寸、交互状态和安全区。
- `index.json`：更新页面标题、背景色和分享相关页面配置。

状态保持页面级、无持久化：心情选择和换一换只在当前页面生命周期内有效。

## 错误与降级

- 素材全部打包为本地小程序资源，不依赖远程图片或网络状态。
- 路由失败时使用 `wx.showToast` 提示用户稍后重试。
- 分享能力由微信环境接管；无法触发时不新增后端或替代分享服务。
- 不新增不存在的个人中心、收藏、商品详情映射或推荐接口。

## 验证

1. 运行小程序 TypeScript 类型检查和现有 Jest 测试。
2. 添加首页行为测试，覆盖路由映射、心情轮换和分享配置。
3. 在微信开发者工具或可用的小程序预览环境中检查首页渲染和主要点击路径。
4. 将同尺寸页面截图与 `homepage_full_mockup.png` 对比，修正高、中优先级的视觉差异。

## 完成标准

- 首页视觉层级、配色、图片使用和信息结构与参考图一致。
- 所有明确入口都能连接到现有页面或微信原生分享。
- 没有引入后端依赖、虚构数据接口或无对应页面的新路由。
- 类型检查和现有自动化测试通过，且视觉对比没有阻断交付的问题。
