# 固定视角 2.5D 手串预览设计规格

最后更新：2026-07-25  
状态：已确认

适用项目：DIY 手串定制商城

## 1. 目标与已确认决策

本阶段把现有 DIY 编辑器中直接绘制商品封面的方式升级为固定视角的写实 2.5D 拼串：

> 运营人员为珠子准备正面、背面和侧面共 3～6 张图片 → 后台自动生成透明背景的固定视角效果素材，也允许人工上传替换 → 小程序 Canvas 按珠径、顺序、遮挡和阴影拼成一串具有 3D 质感的手链。

已经确认：

1. 用户关注的是整串手链的搭配效果，不需要观察单颗珠子的 360° 外观。
2. 不需要旋转整条手串，不需要改变观察相机或实时光线。
3. 前端采用固定视角 2.5D Canvas 合成，不引入 Three.js、WebGL 或 GLB。
4. 后台采用模式 C：自动生成并允许人工替换。
5. Blender 只属于后台异步素材生产工具，不进入商品查询、DIY 编辑、报价、保存或下单的同步链路。
6. 自动生成失败、尚未生成或未发布时，DIY 编辑器必须继续使用现有商品封面或颜色占位，不能阻断选珠、报价和下单。

## 2. 范围

### 2.1 本阶段包含

- 珠子 2.5D 素材版本、源图片、生成任务和发布状态；
- 后台上传 3～6 张源图片；
- 圆珠、切面珠、桶珠、隔片等形状模板；
- 不透明石材、半透明水晶、玻璃和金属等材质预设；
- Blender 无界面异步生成透明背景 PNG/WebP；
- 后台生成、重试、预览、人工替换、发布和回退；
- 小程序公共商品数据返回已发布的 DIY 效果素材；
- Canvas 固定视角拼串、遮挡排序、接触阴影、整串投影和选中态；
- 素材失败降级、缓存版本控制、预览图导出；
- 数据迁移、自动化测试、HTTP 冒烟和多档真机性能验收；
- 当前架构、数据模型、API、后台使用和测试文档更新。

### 2.2 本阶段不包含

- 单颗珠子或整串手链的 360° 旋转；
- GLB、glTF、Three.js、WebGL 或实时 PBR；
- 从单张图片推断真实三维几何；
- 摄影测量、NeRF、Gaussian Splatting；
- AR 手腕试戴；
- 用户请求期间实时运行 Blender；
- 用生成素材替代商品详情封面；
- AI 自动判断商品材质并绕过人工确认；
- 因视觉素材未就绪而禁止珠子上架、报价或下单。

## 3. 总体架构

```text
Vue 管理后台
  ├─ 上传源图片 / 选择形状与材质预设
  ├─ 发起自动生成
  ├─ 查看状态、预览、重试
  ├─ 上传人工替换图
  └─ 发布或回退版本
          │
          ▼
Spring Boot 素材应用服务
  ├─ 权限、参数、状态机、版本和审计
  ├─ 写生成任务，不等待 Blender
  └─ 通过现有 FileStorage 保存输入与输出
          │
          ▼
本地 Blender Worker
  ├─ 领取任务
  ├─ 读取固定程序化模板、预设和允许的参数
  ├─ 后台模式生成透明图
  ├─ 校验尺寸、透明通道和文件大小
  └─ 回写成功或失败
          │
          ▼
已发布 2.5D 素材 URL + 版本
          │
          ▼
微信小程序 Canvas 2D
  ├─ 预加载和缓存
  ├─ 按珠径与顺序计算圆周位置
  ├─ 深度排序、遮挡、接触阴影
  ├─ 绘制固定视角珠子素材
  └─ 导出方案预览图
```

Blender Worker 首版与 Spring Boot 部署在同一受控主机，使用同一后端代码库的
`visual-worker` Spring Profile 作为独立进程运行。它复用数据库访问和 `FileStorage`
适配器，但不启动对外 HTTP 端口。Web 应用只创建数据库任务，不执行 Blender；
Worker 使用固定可执行文件、固定 Python 脚本、固定预设目录和结构化任务参数启动
Blender 子进程。

## 4. 素材规范

### 4.1 源图片

每个珠子版本允许 3～6 张源图片，至少包含：

- `FRONT`：正面；
- `BACK`：背面；
- `SIDE`：侧面。

可选：

- `SIDE_LEFT`；
- `SIDE_RIGHT`；
- `DETAIL`。

源图片要求：

- PNG、JPEG 或 WebP；
- 单张不超过现有文件上传上限；
- 主体完整、无遮挡；
- 使用一致的中性背景和白平衡；
- 图片角色不可重复；
- 发布前由运营人员确认颜色没有明显偏差。

系统不承诺仅凭这些图片恢复珠子真实背面几何。自动流程只把照片用于固定程序化形状模板的颜色、纹理和材质参考。

### 4.2 生成结果

每个可发布版本至少包含：

- `trayAssetId`：珠子选择区小图；
- `canvasAssetId`：DIY Canvas 高清透明背景图。

首版只生成一个固定观察方向。圆珠不按手串位置生成多个角度；异形珠后续如确有视觉问题，可在同一数据模型中扩展 `LEFT`、`CENTER`、`RIGHT` 三个角度，本阶段不提前实现。

输出规范由系统固定，运营人员不可随意修改：

- 正方形画布；
- 透明背景；
- 珠子主体居中；
- 统一相机、焦距、光源方向和色彩空间；
- 主体包围盒留白比例一致；
- Canvas 素材固定为 512×512，选择区素材固定为 160×160；
- Blender 使用固定渲染脚本直接输出透明 WebP，Worker 随后校验尺寸、透明通道和文件大小；
- 发布资产使用 WebP；人工上传允许透明 PNG 或透明 WebP；
- 自动生成的单个 Canvas WebP 目标不超过 200 KB，发布硬上限为 500 KB。

### 4.3 形状和材质预设

首版形状预设：

- `ROUND`：圆珠；
- `FACETED`：切面珠；
- `BARREL`：桶珠；
- `SPACER`：隔片或金属片。

首版材质预设：

- `OPAQUE_STONE`：不透明石材；
- `TRANSLUCENT_CRYSTAL`：半透明水晶；
- `GLASS`：玻璃；
- `METAL`：金属。

预设映射到受控 Blender 模板参数。后台只展示业务名称和少量安全参数，不开放节点图、Python 表达式、文件路径、相机、灯光或渲染器底层设置。

## 5. 数据模型

不把 2.5D 素材直接追加到 `bead_sku.cover_asset_id`。商品封面和 DIY 效果素材用途、审核和生命周期不同，必须分开。

`bead_sku` 新增可空的 `published_visual_version_id` 外键，作为当前生效版本的唯一事实
来源。公共查询只通过该指针读取素材。发布事务锁定 `bead_sku` 行、归档旧版本并更新
该指针，从结构上避免并发发布后出现两个生效版本。

### 5.1 `bead_visual_version`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `bead_sku_id` | 所属 SKU |
| `version_no` | SKU 内递增版本 |
| `source_type` | `AUTO` 或 `MANUAL` |
| `shape_preset` | 形状预设 |
| `material_preset` | 材质预设 |
| `status` | 版本状态 |
| `tray_asset_id` | 选择区素材，可为空 |
| `canvas_asset_id` | DIY 高清素材，可为空 |
| `failure_code` | 机器可识别失败码，可为空 |
| `failure_message` | 脱敏后的运营提示，可为空 |
| `created_by` | 管理员操作标识；当前保存 JWT 用户名 |
| `published_by` | 发布管理员操作标识；当前保存 JWT 用户名，可为空 |
| `published_at` | 发布时间，可为空 |
| `created_at/updated_at` | 审计时间 |

约束：

- `(bead_sku_id, version_no)` 唯一；
- `bead_sku.published_visual_version_id` 必须指向属于该 SKU 的 `PUBLISHED` 版本；
- `PUBLISHED` 必须同时具有可用的 `tray_asset_id` 和 `canvas_asset_id`；
- 发布新版本时在同一事务内把旧发布版本变为 `ARCHIVED`；
- 已被方案预览使用的 `asset_file` 不立即物理删除。

### 5.2 `bead_visual_source`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `visual_version_id` | 素材版本 |
| `role` | `FRONT`、`BACK`、`SIDE` 等 |
| `asset_file_id` | 现有 `asset_file` 主键 |
| `sort_order` | 稳定顺序 |
| `created_at` | 创建时间 |

同一版本的 `role` 唯一。人工替换版本可以没有源图片，但必须记录人工上传的输出素材。

### 5.3 `bead_visual_job`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `visual_version_id` | 待生成版本 |
| `status` | 任务状态 |
| `attempt_count` | 已执行次数 |
| `max_attempts` | 最大次数 |
| `worker_id` | 领取任务的 Worker，可为空 |
| `lease_until` | 任务租约，可为空 |
| `started_at/finished_at` | 执行时间 |
| `failure_code/message` | 脱敏失败信息 |
| `created_at/updated_at` | 审计时间 |

任务领取使用数据库原子状态更新或行锁；Worker 崩溃后租约到期可重新领取。任务幂等键为素材版本 ID，同一版本同一时刻只能有一个未终结任务。

### 5.4 `diy_visual_config`

全局只开放直接影响小程序拼串的少量业务参数：

| 字段 | 默认值与约束 |
| --- | --- |
| `canvas_background_color` | `#fffdfb`，合法十六进制颜色 |
| `bracelet_shadow_opacity` | `0.16`，范围 `0～0.40` |
| `bead_shadow_opacity` | `0.20`，范围 `0～0.50` |
| `bead_overlap_ratio` | `0.06`，范围 `0～0.15` |
| `config_version` | 每次成功保存递增 |
| `updated_by/updated_at` | 审计字段 |

该配置随现有 DIY 公共配置返回。相机、灯光、纹理节点、渲染器、输出尺寸和压缩参数
不属于运营配置，继续由模板与部署配置固定。

### 5.5 状态机

素材版本：

```text
DRAFT
  ├─ 自动生成 → GENERATING → READY → PUBLISHED
  │                         └→ FAILED → GENERATING
  └─ 人工上传 ─────────────→ READY → PUBLISHED

PUBLISHED → ARCHIVED
READY / FAILED / ARCHIVED → 重新制作新版本
```

生成任务：

```text
PENDING → RUNNING → SUCCEEDED
                  ├→ RETRYABLE_FAILED → PENDING
                  └→ TERMINAL_FAILED
```

不在同一素材版本上覆盖已经发布的二进制文件。重新生成或人工替换都创建新版本，便于审计、缓存刷新和一键回退。

## 6. 后台产品设计

在现有珠子编辑表单增加“DIY 效果素材”卡片，而不是新建与商品割裂的独立目录。

### 6.1 展示内容

- 当前发布状态；
- 当前发布版本和来源；
- 选择区预览；
- DIY Canvas 预览；
- 最近失败原因；
- 最近更新时间和操作人；
- “上传源图片”“自动生成”“人工替换”“发布”“重试”“回退”操作。

### 6.2 自动生成

1. 管理员上传 3～6 张图片并标记正、反、侧角色；
2. 选择形状和材质预设；
3. 前端校验角色、格式和大小；
4. 后端重新校验并创建 `DRAFT` 版本；
5. 点击生成后创建任务，版本进入 `GENERATING`；
6. 页面轮询低频状态或由管理员手动刷新；
7. 成功后版本进入 `READY`，管理员对照原商品确认；
8. 管理员显式点击发布，公共接口才开始返回新素材。

生成成功不自动发布，避免颜色、透明感或裁切错误直接影响用户。

### 6.3 人工替换

人工替换必须上传：

- 选择区透明 PNG/WebP；
- DIY Canvas 透明 PNG/WebP。

后台校验图片尺寸、透明通道、文件大小和主体包围盒。人工替换创建 `MANUAL/READY` 新版本，不覆盖自动版本；管理员确认后发布。

### 6.4 权限和审计

生成和上传沿用商品编辑权限；发布、回退要求商品发布权限。全局 DIY 视觉配置沿用
现有 DIY 配置权限。所有生成、失败、人工替换、发布和回退记录管理员、时间、SKU 和版本。

## 7. Blender Worker

### 7.1 职责边界

Worker 只做以下工作：

1. 领取结构化任务；
2. 读取已登记的源 `asset_file`；
3. 根据白名单形状和材质选择仓库内固定的程序化形状模板与材质预设；
4. 运行固定 Python 脚本装配纹理和参数；
5. 固定相机和灯光渲染透明 WebP；
6. 生成选择区、Canvas 两个尺寸；
7. 校验输出；
8. 通过 `FileStorage` 对应的受控写入接口保存素材并回写结果。

Worker 不接受管理员提交的脚本、模板路径、输出路径或任意 Blender 参数。

### 7.2 运行和配置

技术配置放在服务端环境变量或部署文件：

- Blender 可执行文件路径；
- 固定脚本和预设目录；
- Worker ID；
- 并发数；
- 单任务超时；
- 最大重试次数；
- 临时目录；
- 输出尺寸和文件上限。

本地开发允许禁用 Worker。禁用时仍可使用人工上传模式，公共商品和 DIY 功能不受影响。

### 7.3 安全

- 临时目录按任务创建，不使用源文件名拼接路径；
- 任务参数只接受枚举和数值白名单；
- 禁止从数据库或上传内容执行 Python；
- 进程使用低权限账号；
- 限制 CPU、内存、任务时长和输出大小；
- 日志不记录本地绝对存储路径、令牌或用户隐私；
- 失败信息映射为稳定错误码和安全运营文案。

## 8. API 设计

以下为语义接口，具体路径遵循现有 `/api/admin/**`、`/api/public/**` 风格。

### 8.1 管理接口

- `GET /api/admin/catalog/beads/{skuId}/visuals`
  - 返回当前发布版本、历史版本和进行中任务摘要。
- `POST /api/admin/catalog/beads/{skuId}/visuals/auto`
  - 创建自动生成草稿，接收源素材 ID、角色、形状和材质预设。
- `POST /api/admin/catalog/beads/{skuId}/visuals/{versionId}/generate`
  - 发起幂等生成任务。
- `POST /api/admin/catalog/beads/{skuId}/visuals/manual`
  - 创建人工替换版本。
- `POST /api/admin/catalog/beads/{skuId}/visuals/{versionId}/publish`
  - 发布 READY 版本。
- `POST /api/admin/catalog/beads/{skuId}/visuals/{versionId}/retry`
  - 为 FAILED 自动版本重新排队。
- `POST /api/admin/catalog/beads/{skuId}/visuals/{versionId}/rollback`
  - 以指定历史版本的素材创建并发布一个新版本，保留审计链。
- `GET /api/admin/diy/visual-config`
  - 读取全局拼串视觉配置。
- `PUT /api/admin/diy/visual-config`
  - 校验并保存全局拼串视觉配置，递增配置版本。

生成和重试接口返回任务 ID 与当前状态，不等待 Blender 完成。

### 8.2 公共接口

现有 `BeadSkuSummary`、`BeadSkuDetail` 和 DIY 方案目录快照增加可空字段：

```json
{
  "diyVisual": {
    "trayUrl": "/api/public/files/...",
    "canvasUrl": "/api/public/files/...",
    "version": 3
  }
}
```

只返回 `bead_sku.published_visual_version_id` 指向的 `PUBLISHED` 版本。未发布时
`diyVisual` 为 `null`，小程序使用 `coverUrl`，再失败则使用颜色占位。

版本号参与客户端缓存键。URL 仍由服务端从 `asset_file` 解析，前端不得根据素材主键猜测路径。
现有 DIY 公共配置同时返回 `visualConfig` 和 `configVersion`。

## 9. 小程序 Canvas 渲染

### 9.1 数据优先级

```text
已发布 canvasUrl
  → 商品 coverUrl
  → 根据商品颜色生成的圆形占位
```

珠子选择区使用 `trayUrl → coverUrl → 颜色占位`。

### 9.2 布局

继续以方案的有序 SKU ID 数组为唯一事实来源，继续复用珠径和当前 `layoutBracelet` 计算。新增的视觉布局信息只用于绘制，不写入方案。

每个绘制项包含：

- 圆周中心点；
- 由珠径换算的逻辑半径；
- 图片显示矩形；
- 圆周角度；
- 深度值；
- 是否选中；
- 素材 URL 和版本。

首版保持当前正视圆形手串构图，并使用服务端返回的背景、阴影和重叠配置。为产生固定
视角立体感：

1. 先画整串柔和投影；
2. 再画绳线；
3. 按深度从后向前绘制珠子；
4. 每颗珠子绘制轻量接触阴影；
5. 再绘制透明素材；
6. 最后绘制选中轮廓和编辑提示。

素材自身包含主要高光和暗部。Canvas 不重复叠加强高光，避免塑料感。

### 9.3 尺寸和命中

- 珠子视觉直径以商品 `diameterMm` 为基础；
- 图片透明留白不能影响命中区域；
- 触摸命中仍以逻辑圆或异形预设的简化包围盒计算；
- 选中轮廓独立绘制，不修改素材；
- 拖动过程中可降低阴影质量，但触摸结束后恢复完整绘制。

### 9.4 加载和性能

- 只预加载当前方案和可见选择区需要的素材；
- 同一 SKU/版本只创建一次 CanvasImage；
- 限制并发下载；
- 单图失败不触发全画布失败；
- 页面卸载时释放不再使用的引用；
- 重绘使用节流，并避免图片加载回调造成无限重绘；
- 不把大图以 Base64 放进接口 JSON；
- 首版不引入 KTX、GLB 或运行时图片滤镜。

性能验收以包含 60 颗珠子的方案为上限，在低、中、高三档真实 Android 设备和一台 iPhone 上验证首次可见、拖动、替换和导出。

## 10. 错误处理与降级

### 10.1 后台

- 源图片不足或角色重复：拒绝创建自动版本；
- Blender 未安装或 Worker 禁用：任务保持明确的不可用/失败状态，提示改用人工上传；
- 超时或临时进程失败：在最大次数内重试；
- 模板、参数或输出校验失败：终结失败，等待人工处理；
- 人工图没有透明通道或超过上限：拒绝保存；
- 发布时版本不是 READY：返回业务错误；
- 并发发布：事务内锁定 `bead_sku`，归档旧版本并更新
  `published_visual_version_id`，确保只有一个当前生效版本。

### 10.2 小程序

- `diyVisual` 为空：使用封面；
- 2.5D 图片下载失败：本次会话标记失败并使用封面，不循环重试；
- 封面也失败：使用颜色占位；
- 单颗素材失败：只降级该颗；
- Canvas 导出失败：沿用现有方案已保存、预览稍后重试语义；
- 视觉素材切换不影响价格、库存、报价指纹、BOM 或订单状态。

## 11. 测试策略

### 11.1 后端

- 素材版本状态机和发布事务；
- SKU 当前发布版本指针的归属和状态校验；
- 自动版本源角色校验；
- 人工版本输出素材校验；
- 生成接口幂等；
- Worker 任务领取、租约过期和重试；
- 新版本发布时旧版本归档；
- 公共接口只返回已发布素材；
- 未发布或素材失效时公共接口返回 `null`；
- 管理权限和发布权限；
- 全局视觉配置范围、版本递增和公共返回；
- 文件路径、枚举白名单和脱敏错误。

测试不依赖本机真实 Blender。应用服务使用 `VisualGenerationGateway` 测试替身；另提供显式 opt-in 的本地 Blender 集成测试。

### 11.2 管理后台

- 3～6 张源图和角色校验；
- 自动生成状态展示；
- 轮询停止条件；
- 失败、重试和人工替换；
- 未 READY 不允许发布；
- 发布确认和历史版本回退；
- 请求失败保留用户输入。

### 11.3 小程序

- `canvasUrl → coverUrl → 颜色` 优先级；
- 不同直径的缩放；
- 深度排序稳定；
- 图片异步完成后的有限重绘；
- 单图失败局部降级；
- 选中、拖动、替换、撤销和重做不改变顺序语义；
- 60 颗珠子的布局、命中和预览导出；
- 保存和恢复方案后使用同一发布版本或最新公共版本的明确行为。

方案只保存 SKU 顺序，不固定视觉版本；再次打开时使用该 SKU 当前已发布视觉版本。订单中的既有方案预览图仍是下单时的静态快照，不随素材发布变化。

### 11.4 验收素材

至少准备：

- 3 款圆珠：深色不透明、浅色不透明、半透明；
- 1 款切面珠；
- 1 款金属隔片；
- 1 个自动生成失败后人工替换的案例；
- 1 个混合不少于 20 颗的手串；
- 1 个达到 60 颗上限的性能方案。

## 12. 迁移与发布顺序

1. 新增数据表和服务端领域模型，不改变现有公共返回；
2. 完成人工上传、发布和公共查询，先打通无 Blender 的完整链路；
3. 小程序读取可空 `diyVisual` 并实现写实 Canvas 合成和降级；
4. 后台接入自动生成任务；
5. 部署 Blender Worker、固定程序化模板和材质预设；
6. 用少量 SKU 灰度生成并人工发布；
7. 完成多档真机性能和视觉验收；
8. 批量补齐其余珠子素材。

该顺序保证即使 Blender Worker 尚未完成，人工模式和前端 2.5D 链路也已经可交付。

## 13. 成功标准

- 运营人员可以为任一珠子自动生成或人工上传 2.5D 素材；
- 未经人工发布的素材不会出现在小程序；
- 自动生成失败可改用人工替换，不阻断商品业务；
- DIY 页面可以把不同材质和直径的珠子拼成固定视角、具有明显立体感的手串；
- 编辑、拖动、撤销、报价、保存和导出保持可用；
- 60 颗珠子在约定真机范围内没有持续卡顿或崩溃；
- 2.5D 素材故障不会影响报价、库存、订单和履约；
- 不引入 Three.js、WebGL 或用户请求期间的 Blender 调用。
