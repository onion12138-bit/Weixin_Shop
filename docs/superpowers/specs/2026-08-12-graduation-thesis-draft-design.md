# 毕业论文初稿设计规格

## 1. 文档目标

- 课题名称：基于 SpringBoot 的微信小程序 DIY 商品系统设计与实现。
- 成果形态：可在 Microsoft Word 中继续修改的 `.docx` 初稿。
- 模板依据：`/Users/onion/Desktop/qqw/上海大学继教毕业设计(论文)模版-26新版.doc`。
- 内容依据：当前项目代码、数据库迁移、自动化测试、项目文档，以及《开题报告》《任务书》确定的研究目标和八章提纲。
- 篇幅口径：按学位论文标准准备，正文目标不少于 12000 个汉字，不以摘要、目录、参考文献和附录凑字数。
- 原创性原则：围绕本项目的业务建模、技术取舍、实现过程和测试证据独立撰写；不复制或拼接公开论文，不虚构引用，不承诺第三方查重系统的确定数值。

## 2. 模板与版式

- 从只读转换后的学校模板副本创建，不覆盖原始 `.doc`。
- 保留学校封面、声明书、承诺书、校徽、页眉和页码体系，删除模板中的示例文字和格式说明气泡。
- 封面中的专业、年级、班级、学号、姓名、指导教师暂写“待填写”。
- A4 纵向；上、下边距 2.5 cm，左边距 3.0 cm，右边距 2.0 cm。
- 正文中文为宋体小四，西文为 Times New Roman，小四，1.5 倍行距，首行缩进 2 个字符。
- 一级标题使用黑体小二、居中、另起一页；二级标题黑体小三；三级标题黑体四号；四级标题黑体小四。
- 建立真实的 Word 标题样式和可更新目录。目录不显示页码；中文摘要开始显示正文页码。
- 图、表按章编号，图题和表题使用宋体五号并居中；正文必须先引用再出现图表。

## 3. 内容结构与篇幅分配

### 前置部分

1. 中文摘要：300—500 字，说明问题、方法、实现范围、验证结果和结论；关键词 3—5 个。
2. 英文摘要：与中文摘要信息一致，不添加中文摘要中没有的成果。
3. 目录：覆盖摘要、八章正文、致谢、参考文献和附录。

### 第一章 绪论，约 1500—1800 字

- 研究背景及意义。
- 国内外研究与应用现状。
- 研究内容、研究方法和技术路线。
- 论文组织结构。
- 与开题报告一致，以 DIY 手串为主要业务样例，同时使用“DIY 商品系统”作为可扩展课题边界。

### 第二章 相关技术介绍，约 1500—1800 字

- 微信小程序运行机制和原生开发模式。
- Spring Boot 与 RESTful API。
- Vue 3、TypeScript 与后台管理端。
- MySQL、Flyway 数据库版本管理和事务。
- JWT、文件存储、测试工具与 AI 推荐接口。
- 只说明本项目实际使用或明确预留的技术，不将 Redis、对象存储等未落地能力写成已部署。

### 第三章 系统需求分析，约 1800—2200 字

- 系统角色：游客/顾客、管理员、外部服务。
- 用户端需求：商品浏览、详情、收藏、个人资料、收货地址、优惠券、DIY 编辑、方案、推荐、订单和模拟支付。
- 管理端需求：商品与 SKU、图片、DIY 规则、价格、库存补货、客户权益、订单履约、AI 配置及日志。
- 后端需求：身份、权威报价、库存预占、订单状态、文件存储、日志和异常处理。
- 非功能需求：正确性、安全性、可维护性、可测试性、兼容性和可扩展性。
- 可行性分析和业务流程分析。

### 第四章 系统总体设计，约 1800—2200 字

- 微信小程序、Vue 管理端、Spring Boot 服务端和 MySQL 数据库的三端架构。
- 商品、客户、DIY、推荐、库存、订单、履约、文件和后台配置模块划分。
- RESTful 接口、认证授权、统一错误返回和第三方能力隔离。
- DIY 方案保存与报价、下单与库存预占、取消与优惠券返还、发货与订单日志等关键流程。
- 图示至少包括系统架构图、功能模块图和两个关键业务流程图。

### 第五章 数据库设计与接口设计，约 1800—2200 字

- 数据库概念设计和主要实体关系。
- 结合 V1—V16 迁移说明商品分类、商品、SKU、DIY 方案、订单、库存流水、客户资料、地址、收藏、优惠券、推荐包、履约日志和 AI 日志等表。
- 解释有序 SKU 序列、后端权威计价、库存预占及释放、优惠券状态恢复等数据一致性设计。
- 给出核心表结构和代表性接口，不在正文逐项罗列全部字段或接口。
- 图示至少包括核心 ER 图；表格包括主要数据表说明和核心接口说明。

### 第六章 系统主要功能实现，约 3000—3500 字

- 后端模块组织、接口分层和关键事务实现。
- 商品目录、图片上传与本地文件存储。
- DIY 2.5D 固定视图编辑、珠子排列、尺寸调整、方案保存和权威报价。
- 首页推荐包和 AI 多方案推荐，说明密钥加密、软偏好和观测日志。
- 顾客资料、地址、收藏、优惠券和订单确认。
- 库存补货、库存预占、统一履约、状态历史和操作日志。
- Vue 管理后台的运营配置与日志页面。
- 每个实现小节包含“业务目的—实现过程—关键技术—结果”的完整叙述，避免只贴代码。
- 使用最新、可识别的项目界面截图，并隐去不适合公开的密钥或个人数据。

### 第七章 系统测试与结果分析，约 1600—2000 字

- 测试环境、测试策略和验收标准。
- 后端单元测试、接口/数据库集成测试，管理端 Vitest、TypeScript 类型检查和构建，小程序 Jest 与类型检查。
- 记录历史完整验证结果，并如实说明 2026-08-12 当前环境因 Docker 未启动导致 Testcontainers/MySQL 集成测试无法重新执行；不把环境错误表述为功能断言失败。
- 当前可确认结果：管理端 11 个测试文件、92 项测试通过；小程序 26 个测试套件、192 项测试通过；两端类型检查和构建通过。
- 使用测试用例表覆盖 DIY 报价、库存不足、订单取消、优惠券返还、履约状态和异常输入。
- 分析测试覆盖范围、局限和后续补测事项。

### 第八章 总结与展望，约 800—1000 字

- 总结三端系统、DIY 业务闭环和工程验证成果。
- 明确当前仍采用模拟支付、本地文件存储，微信授权、真实支付、对象存储、实时物流和生产环境 AI 成功链路仍待后续接入与验收。
- 展望性能优化、真实微信生态对接、云存储、推荐数据闭环和可观测性完善。

### 后置部分

- 致谢：独立、克制，不虚构导师姓名或具体帮助。
- 参考文献：不少于 15 条，其中至少 2 条英文；优先近五年可核验的学术论文、专著和官方技术资料，按 GB/T 7714 风格排列，并确保正文存在对应引用。
- 附录：附一份与本系统相关、由本文自行组织的英文技术说明及不少于 800 字的中文翻译；明确其为论文附录技术材料，不冒充转载论文。如学校要求必须使用导师认可的公开英文文献，初稿中保留可替换提示。

## 4. 事实边界

### 已实现并可写入成果

- Spring Boot 后端、Vue 3 管理后台、原生微信小程序三端结构。
- 商品、分类、SKU、图片、DIY 方案、规则与报价。
- 2.5D 手串预览、珠子排列、尺寸及交互优化。
- 顾客资料、地址、收藏、优惠券和首页推荐。
- 库存预占、库存流水、补货、订单、模拟支付、履约和操作日志。
- AI 多方案推荐的配置、偏好、密钥保护、日志和后台观测能力。

### 只能作为局限或扩展方向

- 微信正式授权登录、真实微信支付与退款。
- 对象存储、生产级 CDN、实时物流接口。
- 生产环境大规模性能数据和未完成的 DeepSeek 线上成功验收。
- Redis 只能作为预留方案讨论，不能写成当前运行依赖。
