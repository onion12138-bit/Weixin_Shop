# DIY 方案体验修复设计

## 目标

修复 DIY 方案列表、编辑器和后台成品推荐中的五项体验问题，同时保留现有页面面积、数据模型与报价流程。

## 方案列表缩略图

方案卡片保持现有预览区域高度。预览图改为完整适配显示，避免方形手串画布在横向卡片中被裁切；多出的区域沿用卡片背景色。这样整串手串始终可见，不会扩大卡片。

## 每位顾客最多三套 DIY 方案

后端在创建和复制活动方案前，按当前顾客的活动方案数量执行上限校验；更新既有方案不受影响。超过上限时返回明确的业务错误，保证不能通过直接调用接口绕过规则。

方案列表在本地已有三套方案时不再进入空白编辑页，而是用 Toast 提示“最多保存 3 个 DIY 方案”。服务端仍是最终约束，处理并发和其他客户端的创建请求。

## 后台推荐反馈

成品推荐和取消推荐成功时显示短时 Toast。页面不再渲染顶部的成功提示条，错误提示和表单保存反馈维持当前可见、可访问的形式。

## 编辑器首次加载

编辑器在页面和 Canvas 已挂载后，以不透明 Loading 覆盖层遮住内容。首次要显示的手串珠子图片全部完成加载（包括图片失败后的降级路径）后才移除覆盖层。加载期间不显示带阴影的圆形占位珠。

## 已保存方案的珠子操作栏

珠子操作栏始终显示。打开既有方案时默认不选中珠子，计数显示 `0`；此时减号、加号、替换和删除均不执行操作。用户点击手串上的某颗珠子后，操作栏显示其序号并启用相应操作。

## 验证

- 小程序单测覆盖：完整缩略图模式、三套方案前端 Toast、后端上限错误映射、初始未选中时操作栏状态、首次图片加载期间的 Loading。
- 后端集成测试覆盖：第三个方案允许创建，第四个活动方案被拒绝，删除后可重新创建。
- 后台组件测试覆盖：推荐成功显示 Toast，顶部成功横幅不存在。
- 执行小程序测试和类型检查、后台相关测试、后台前端构建与测试；提交前检查工作区和差异。
