# 商品闭环修复与 AI 单套推荐设计

日期：2026-07-12

## 1. 背景与目标

当前小程序固定访问 `http://localhost:8080/api`，但本机 8080 由 Jenkins 占用。真实请求返回 Jenkins 403，项目 Spring Boot 实际运行在 8081，因此商品目录、访客会话、直接 DIY 和方案相关页面同时失败。

本阶段采用分阶段纵向闭环，目标是：

1. 统一本地三端 API 地址，消除小程序请求 Jenkins 的问题；
2. 从 `Pic/` 合集图中裁切三款珠子，通过真实后台接口上传、创建商品并初始化库存；
3. 确保后台新增并上架的珠子可以立即被小程序目录、详情和 DIY 编辑器读取；
4. 增加一套可由后台维护的 DeepSeek 配置；
5. 在小程序增加结构化咨询入口，调用 DeepSeek 生成一套经过后端校验的 DIY 方案。

本阶段不实现多轮聊天、多模型配置、规则降级、真实微信登录、真实支付或对象存储。

## 2. 已确认决策

- 实施方式：分阶段纵向闭环；
- 本地项目后端固定使用 8081，不再自动选择会导致小程序失配的其他端口；
- 首批只导入拉长石、石榴石和萤石；
- 三款珠子均为 8mm、库存 200、直接上架；
- DeepSeek 默认模型为 `deepseek-v4-flash`；
- 后台只维护一套当前生效的大模型配置；
- 推荐结果只生成一套方案；
- 咨询采用“结构化表单 + 自由描述”，不实现多轮聊天；
- 支持手动选择星座、生肖，也支持填写出生日期自动推算后再手动覆盖；
- 未配置、停用或调用失败时不执行本地规则降级；
- 星座、生肖、五行和寓意相关内容统一标注“文化娱乐参考”。

DeepSeek 官方当前支持 `deepseek-v4-flash` 与 `deepseek-v4-pro`，本项目选用响应更快、成本更低的 Flash。官方 API 地址保持 `https://api.deepseek.com`。

## 3. 分阶段交付

### 3.1 阶段一：本地请求稳定性

- Spring Boot、本地 `.env.example`、管理后台、小程序、冒烟脚本和文档统一使用 8081；
- 一键启动脚本必须在 8081 已被本项目占用时复用，在被其他程序占用时明确失败，不得静默改成 8082；
- Jenkins 8080 不被结束或修改；
- 小程序 API 地址集中在环境配置模块，不再散落硬编码；
- 访客 Token 首次收到 401 时只刷新一次，第二次失败返回明确错误；
- 修复首页“开始选珠”、直接 DIY、商品目录、详情和方案入口的真实请求。

### 3.2 阶段二：三款商品真实闭环

从 `Pic/530cd765-4340-4b78-a3f2-95bb3a4fb80d.png` 的规则网格中确定性裁切：

- 第一行左侧：拉长石；
- 第一行右侧：石榴石；
- 第二行左侧：萤石。

裁切保持原始商品内容，不使用生成式图像改写。派生图保存到受 Git 管理的演示素材目录，原始 `Pic/` 不覆盖、不提交。重复源图不重复处理。

商品数据：

| SKU | 名称 | 材质 | 颜色 | 售价 | 成本 | 库存 | 标签 |
| --- | --- | --- | --- | ---: | ---: | ---: | --- |
| `BEAD-LABRADORITE-8MM` | 拉长石 8mm | 天然水晶 | 灰蓝色 | 9.80 | 2.80 | 200 | 灵感、守护、灰蓝、通勤 |
| `BEAD-GARNET-8MM` | 石榴石 8mm | 天然水晶 | 酒红色 | 9.50 | 2.50 | 200 | 活力、热情、红色、日常 |
| `BEAD-FLUORITE-8MM` | 萤石 8mm | 天然水晶 | 紫绿色 | 8.80 | 1.80 | 200 | 专注、平衡、紫绿、学习 |

三款商品归入“天然水晶”，状态为 `ON_SALE`，库存预警阈值为 20。

后台创建珠子增加 `initialStock`。POST 创建接口使用独立的创建 DTO，在同一事务中写入：

1. `bead_sku`；
2. `inventory_balance`；
3. `inventory_ledger` 的 `INIT` 流水。

PUT 编辑接口不接受初始库存，避免商品资料编辑覆盖现有库存。导入脚本通过管理员登录、素材上传和商品创建 API 工作，以 SKU 作为幂等键；不直接向数据库插入演示商品。

公开目录继续只返回 `ON_SALE` 商品。后台保存成功后，小程序刷新即可读取相同 SKU 和 `coverUrl`。图片加载失败使用占位图，不阻断其他商品。

### 3.3 阶段三：DeepSeek 后台配置

新增单例表 `ai_model_config`：

- `id`：固定单例主键；
- `provider`：当前只允许 `DEEPSEEK`；
- `base_url`：默认 `https://api.deepseek.com`；
- `model_name`：默认 `deepseek-v4-flash`；
- `encrypted_api_key`：可空；
- `enabled`；
- `timeout_seconds`；
- `max_output_tokens`；
- `version`、创建时间和更新时间。

API Key 使用 AES-GCM 加密，主密钥来自 `AI_CONFIG_ENCRYPTION_KEY`。主密钥不得写入数据库、Git、接口响应或日志。后台查询只返回 `apiKeyConfigured`。保存请求中 API Key 留空代表保留原值，清除必须走显式操作。

第一版 Provider 固定为 DeepSeek。Base URL 必须为 HTTPS 且主机为官方 `api.deepseek.com`，避免后台配置形成 SSRF。模型名默认 `deepseek-v4-flash`，允许管理员修改为 DeepSeek 当前可用模型。

后台接口：

- `GET /api/admin/ai/config`；
- `PUT /api/admin/ai/config`；
- `POST /api/admin/ai/config/test`；
- `DELETE /api/admin/ai/config/api-key`。

测试连接调用 DeepSeek `/models`，检查鉴权和配置模型是否存在。失败响应区分未授权、模型不存在、超时、限流和上游不可用，不回传上游敏感响应体。

后台新增“AI 模型配置”页面，提供保存、测试连接、启停和清除 API Key。API Key 输入框永不回显已有密钥。

### 3.4 阶段四：小程序单套 AI 推荐

首页增加“AI 灵感推荐”入口。可从 `Pic/32b3f736-c48a-446d-a800-230ee2d91579.png` 派生压缩版水元素形象作为入口素材，原图不覆盖。

推荐表单字段：

- 出生日期，可选；
- 星座，可手动选择；
- 生肖，可手动选择；
- 五行偏好，手动选择；
- 心愿；
- 使用场景；
- 颜色偏好；
- 预算；
- 腕围；
- 松紧度；
- 自由描述。

出生日期只推算公历星座和生肖。五行不根据生日自动推断，避免缺少出生时间时提供伪精确结果。自动推算结果允许手动覆盖。出生日期和完整咨询文本不持久化。

应用接口：

- `GET /api/app/recommendations/status`：返回可用、未配置或停用；
- `POST /api/app/recommendations`：需要顾客 JWT，生成单套推荐。

推荐服务先查询当前已上架且库存可用的 SKU，将受控字段发送给 DeepSeek：SKU ID、名称、材质、颜色、直径、售价、标签和可用库存。提示词要求 JSON 输出：

- 方案名；
- 有序 SKU ID 数组；
- 每个 SKU 的数量；
- 推荐说明；
- 每款珠子的选择原因。

DeepSeek 适配器使用 Java 17 `HttpClient` 调用 `/chat/completions`，请求 JSON 输出，不在日志记录 Authorization、出生日期或完整咨询文本。第一版不自动重试，避免重复费用；用户可以主动点击重试。

模型结果必须经过后端校验：

1. SKU 必须来自本次候选集合；
2. SKU 必须保持上架且库存足够；
3. 数量必须为正整数；
4. 组合长度必须满足腕围、余量和最大珠数规则；
5. 价格由后端重新计算且不超过预算；
6. 文案长度和字段必须符合响应契约。

任一校验失败都不向小程序返回半成品方案。

结果页显示方案名、商品图片、数量、有序预览、说明、后端价格和“文化娱乐参考”。点击“一键进入 DIY”时，将结果作为一次性本地临时草稿传给编辑器；只有用户主动保存时才写入 `diy_scheme`。

## 4. 状态与错误契约

- `AI_NOT_CONFIGURED`：未配置 API Key；
- `AI_DISABLED`：管理员停用；
- `AI_UNAUTHORIZED`：DeepSeek 鉴权失败；
- `AI_MODEL_UNAVAILABLE`：模型不存在或不可用；
- `AI_RATE_LIMITED`：上游限流；
- `AI_TEMPORARILY_UNAVAILABLE`：超时或上游故障；
- `AI_INVALID_RECOMMENDATION`：模型输出无法通过契约或业务校验。

小程序对应显示：

- 未配置：AI 推荐暂未开放；
- 停用：AI 推荐暂停使用；
- 其他调用失败：AI 推荐服务暂时不可用，请稍后重试。

不实现规则降级，不伪造推荐结果。

## 5. 安全与隐私

- DeepSeek API Key 只在服务端解密和使用；
- API Key 永不返回前端、永不写入日志；
- AES-GCM 每次加密使用随机 nonce；
- DeepSeek Base URL 仅允许官方 HTTPS 主机；
- 推荐 Prompt 只包含必要的用户选择和候选商品字段；
- 出生日期、自由描述和模型原始响应不写入业务数据库；
- 后端日志只记录 traceId、结果状态、耗时、模型名和候选数量；
- 文化娱乐文案不得承诺健康、财运、感情或其他确定效果。

### 6.1 自动化测试

- 后端：端口配置、访客会话、商品创建库存事务、加密往返、密钥掩码、配置验证、DeepSeek 适配器、上游错误映射、模型 JSON 校验、SKU/库存/预算/腕围校验；
- 管理后台：初始库存字段、三款商品展示、AI 配置保存、Key 不回显、测试连接状态；
- 小程序：API 环境地址、401 单次刷新、商品图片 URL、出生日期推算、手动覆盖、表单校验、AI 状态、结果展示和临时草稿进入 DIY；
- 导入：裁切尺寸、三个文件存在、幂等 SKU 导入和库存初始化。

### 6.2 真实验证

1. `localhost:8080` 仍属于 Jenkins，项目所有客户端不再请求该端口；
2. 8081 的访客会话、目录、DIY 和订单接口正常；
3. 三款图片通过真实上传接口生成 `asset_file`，三款商品通过真实后台接口创建并上架；
4. 三款库存均为 200，并存在对应 `INIT` 流水；
5. 后台能看到图片与商品，小程序列表、详情和 DIY 能读取同一数据；
6. 未配置 AI Key 时小程序显示暂未开放；
7. 配置有效 DeepSeek Key 后测试连接成功；
8. 真实请求生成一套后端验证后的方案并进入 DIY；
9. 全仓验证、商品/DIY/推荐 HTTP 冒烟和微信开发者工具页面验收通过。
