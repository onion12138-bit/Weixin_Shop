# 需求规格说明

最后更新：2026-07-04

## 1. 产品目标

交付一个真实可操作的 DIY 手串商品系统，而不是静态展示页。系统由 Spring Boot
后端、Vue 3 管理后台和原生微信小程序组成，覆盖商品维护、自由排珠、实时计价、
方案保存、下单、模拟支付、库存和履约。

当前阶段不接入真实支付、微信授权和对象存储，但必须通过适配器或配置隔离第三方能力，
使后续替换不改动核心业务流程。

## 2. 用户角色

- 访客/顾客：浏览商品、设计手串、保存方案、提交订单、查看订单。
- 管理员：维护分类、散珠、套餐、素材、库存、订单和履约状态。
- 系统：校验商品状态、计算价格、预占库存、生成生产 BOM 和记录状态变化。

## 3. 功能范围

### 3.1 商品目录（当前阶段）

- 管理分类、散珠 SKU 和套餐。
- 维护材质、颜色、直径、售价、成本价、库存预警值、标签、封面和状态。
- 套餐由有序散珠及数量构成。
- 公共目录仅返回已上架数据，不暴露成本价。
- 支持关键字、分类、状态和分页查询。
- 商品图片限制为 PNG、JPEG、WebP，默认最大 5 MiB。

### 3.2 DIY 设计（待开发）

- 顾客按腕围、珠子直径和顺序进行环形排珠。
- 支持添加、删除、替换、拖动、撤销、重做和清空。
- 实时计算珠子数量、估算周长、商品金额和附加费用。
- 校验下架商品、缺货、尺寸不合理和最大珠子数量。
- 设计器状态与渲染逻辑分离，以便测试和后续更换 Canvas 实现。

### 3.3 方案与推荐（待开发）

- 方案可保存草稿、命名、复制、删除和生成预览图。
- 规则推荐先按预算、色系、材质和场景筛选；智能推荐通过独立适配器后续接入。
- 下单时保存方案快照，避免商品修改影响历史订单。

### 3.4 库存、订单和支付（待开发）

- 库存按散珠 SKU 管理可用量、预占量和流水。
- 提交订单时在事务内校验价格和库存并预占。
- 首版使用模拟支付，支持待支付、已支付、制作中、已发货、已完成和已取消等状态。
- 真实微信支付接入后替换支付适配器，回调必须幂等并验签。
- 超时未支付订单释放库存；支付成功后生成生产 BOM。

### 3.5 管理与审计（待开发）

- 管理员可处理订单、库存调整、发货和退款状态。
- 关键操作保存操作者、时间、业务对象和前后状态。

## 4. 非功能需求

- JDK 17、Spring Boot 3.3、MySQL 8、Vue 3、原生微信小程序。
- 金额使用 `decimal`/`BigDecimal`，禁止浮点金额运算。
- 数据库结构只通过 Flyway 演进。
- 管理接口使用 JWT；密钥和账号只来自环境配置。
- 统一响应含 `code`、`message`、`data`、`traceId`、`timestamp`。
- 关键流程提供单元、Web 和 MySQL 集成测试。
- Java 公共类型和关键规则使用中文 Javadoc；TypeScript 公共逻辑说明状态和边界。

## 5. 阶段验收

### 当前商品目录纵向链路

- 后台可登录并维护散珠，图片可上传到本地目录。
- 小程序可浏览已上架散珠/套餐及详情。
- 管理端接口未认证返回 401，权限不足返回稳定 403 JSON。
- Flyway 可在空 MySQL 8 实例创建结构和演示数据。
- 全仓验证脚本通过后方可合入主开发分支。

### 完整 V1

除上述能力外，必须完成 DIY、方案、库存、订单、模拟支付和履约闭环，才可标记为“完整 V1”。
