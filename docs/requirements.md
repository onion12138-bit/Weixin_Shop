# 需求规格说明

最后更新：2026-10-23

## 1. 产品目标

交付一个真实可操作的 DIY 手串商品系统，由 Spring Boot 后端、Vue 3 管理后台和原生微信小程序组成。当前版本已形成“商品维护/演示导入 → 小程序浏览或 AI 多套灵感 → DIY 排珠 → 权威报价 → 保存方案 → 库存预占 → 创建订单 → 模拟支付 → 制作发货”的本地可用产品闭环。

当前阶段不接入真实微信支付、微信授权和对象存储；本地支付、访客身份与文件存储均保留后续替换边界。模拟支付不会产生真实扣款，不能用于商业收款。

## 2. 用户角色

- 访客/顾客：通过 guest JWT 浏览商品、填写一次性 AI 咨询、查看后台配置数量的服务端复核推荐、进入 DIY，并完成原有方案与订单闭环。
- 管理员：维护商品、素材、DIY/订单；维护唯一 DeepSeek 官方连接配置并显式启停、保存 Key 和测试连接。
- 系统：校验 SKU、尺寸、价格和库存，保护密钥和咨询隐私，只在配置可用时调用模型，并复核模型输出（结构等校验失败最多纠正一次）；没有本地推荐降级。

## 3. 已实现功能范围

### 3.1 商品目录与素材

- 管理珠子、绳类、其他饰品 SKU、套餐、有序套餐明细和封面；只有珠子要求珠径并进入 DIY/AI 链路。
- 公共目录仅返回已上架数据，不暴露成本价。
- 支持关键字、分类、状态和分页查询。
- 商品图片限制为 PNG、JPEG、WebP，最大 5 MB（5,000,000 字节）。
- 散珠商品支持下载 `.xlsx` 模板并批量导入；单次最多 1000 行、10 MB，逐行返回成功或失败原因，图片允许导入后补充。
- 散珠与成品搭配的封面均支持点击选择或拖拽图片直接上传。
- 套餐按 SKU 与数量保存，进入 DIY 时前端临时展开为有序序列。
- 素材当前保存在本地目录，业务只依赖可替换的 `FileStorage`。
- 新增散珠接收 `initialStock`，在同一事务创建库存余额和 `INIT` 流水；3 款图片演示散珠导入会分页查重并按 SKU 幂等跳过。
- 后台列表显示可用、预占、已售库存及预警值；可用库存达到或低于预警值时显示“补货”。

### 3.2 DIY 设计、计价与方案

- 小程序支持从空白、单颗 SKU、套餐和已保存方案进入编辑器。
- 设计状态只保存有序 SKU 数组，不为每颗珠子创建业务 ID。
- 前端支持添加、删除、拖动排序、同 SKU 数量增减；指定某颗珠子后进入替换模式，选择目标 SKU、查看预估差价及尺寸变化，再确认替换。
- 公开散珠列表、详情、套餐内散珠返回当前可用库存，编辑器在材料栏和替换候选中按方案需求量提示缺货；库存是参考，不预留，下单仍需后端重新校验。
- 仅来自历史方案快照的下架珠子可以删除或换出，不能新增数量或作为替换目标；原珠已下架时提示差价无法估算。撤销历史恢复原设计时保留下架/缺货提示。
- 编辑器已接入撤销/重做按钮，最多保留 50 次编辑；一次拖动只算一步，取消拖动/候选替换不产生历史，撤销后继续编辑会清空重做分支。
- 历史包含珠序、选中位置、腕围、松紧和绳材，不回退已保存方案 ID/版本。保存期间禁止修改；重新载入草稿或方案以当前设计作为新历史起点。旧报价/缩略图不会覆盖撤销后的状态，上传预览使用保存时的设计快照。
- 本地预估仅用于即时反馈；最终报价由后端读取当前 SKU、DIY 规则、工艺费和绳材配置计算。
- 后端校验下架/不存在 SKU、最大珠数、腕围、尺寸偏差和绳材可用性。
- 方案支持新建、读取、更新、复制、软删除、乐观锁和预览图；跨访客访问返回 404。
- 方案保存有序 SKU 数组和报价快照；读取时重新评估报价是否过期。

### 3.3 库存与订单

- 每个散珠 SKU 保存可用、预占和已售数量，并记录库存流水。
- 创建订单必须基于当前顾客拥有的有效方案；独立结算报价包含券和运费，提交必须携带报价指纹与稳定令牌，不信任小程序金额。
- 报价返回方案版本；与展示设计不一致时刷新预览和商品信息，并明确确认新设计。价格/规则失效时重新报价，不能自动按新金额下单。
- 同顾客同令牌同请求返回原单；同键改参数拒绝。小程序发送前持久化完整请求，弱网或重新进入先找回结果，未确认前保留原参数。
- 订单保存方案顺序快照、按 SKU 聚合的 BOM、单价快照、总价和收货信息。
- 下单把 `available` 转为 `reserved`；库存不足返回 `INVENTORY_INSUFFICIENT` 且整个订单事务回滚。
- 待支付订单取消或超时关闭把 `reserved` 退回 `available`，归还仍可恢复的券；已过期或撤销的券不会变成可用。
- 新订单默认 30 分钟支付期限，可配置；服务端分批扫描并逐单事务关闭，与支付共用行锁，重复执行不会重复释放。订单返回截止时间、服务器时间及关闭原因，小程序按服务器时间显示倒计时。V18 为历史待支付单保留从迁移时开始的 30 分钟宽限。
- 顾客只能列出和读取本人订单。

### 3.4 模拟支付与履约

- `MOCK` 支付把订单从 `PENDING_PAYMENT` 直接切换为 `IN_PRODUCTION`，库存从 `reserved` 转为 `sold`。
- 重复模拟支付幂等，不重复扣库存、不重复写支付记录和履约任务。已到期时返回关闭状态而非支付成功；新记录明确使用 `MOCK` 和 `MOCK_PAYMENT_SUCCEEDED`。
- 后台“付款提醒”当前只记录操作，明确标示未接入消息发送。
- 支付成功后生成包含订单 SKU 数量的制作任务。
- 正常履约状态机严格为 `PENDING_PAYMENT → IN_PRODUCTION → PENDING_SHIPMENT → SHIPPED → COMPLETED`，不能跳步；异常状态为 `CANCELLED`、`AFTER_SALE`、`REFUNDED`。
- 后台完成制作后进入待发货，发货保存物流公司和运单号；小程序把 `SHIPPED` 展示为“待收货”，顾客确认收货后进入已完成。

### 3.5 三端界面

- 管理后台包含登录、商品目录、DIY 配置、订单与履约工作区。
- 小程序包含首页、目录、详情、DIY 编辑器、我的方案、确认订单、我的订单和订单详情。
- 订单详情明确标注模拟支付，不调用微信支付。

### 3.6 DeepSeek 多套库存材质推荐

- 后台只维护 `id=1/provider=DEEPSEEK` 的单例配置，Base URL 固定官方 `https://api.deepseek.com`，模型固定 `deepseek-v4-flash`；管理员可配置推荐业务提示词、软偏好识别提示词、是否启用软偏好和 1～5 套返回数量，默认 3 套。
- API Key 使用 AES-256-GCM 密文存库，主密钥只来自 `AI_CONFIG_ENCRYPTION_KEY`；普通读取、调优日志和错误不回显 Key 或 Authorization，管理员只有显式点击眼睛按钮才能通过 no-store 接口临时查看。
- 未配置 Key 时状态为 `NOT_CONFIGURED`、POST 为 `AI_NOT_CONFIGURED`、文案为“AI 推荐暂未开放”；停用时对应 `DISABLED`、`AI_DISABLED`、“AI 推荐暂停使用”。
- 系统没有规则、静态或本地降级，暂停和 Provider 故障不能返回伪成功。
- 小程序 AI 表单只保留必填生日和选填期望；生日选定后由公开 Spring Boot 接口计算并展示星座、生肖和星座元素。正式推荐需要 guest JWT。生日、期望、提示词/候选快照、模型请求/原始响应与最终结果默认进入仅管理员可见且可单条删除的调优日志。
- DeepSeek 只可选择服务端当次查询到的当前已上架且有库存 SKU；输入候选包含 `skuId/name/material/color/diameterMm/tags`，不传成本、售价、手围、松紧、数量、排列或绳材。明确的材质、颜色和标签偏好只做软优先，不做后端强制命中。
- 后端严格解析后台配置套数的 JSON，每套限制 3～5 种不同珠子，并重新校验结构、SKU、当前库存和文案；响应包含当前名称、图片、选择理由和文化娱乐免责声明。
- 格式、套数、SKU 或文案校验失败时，同一 DeepSeek 模型最多纠正一次；鉴权、限流、超时和上游故障不重试，不切换其他模型。
- 小程序选择某套进入 DIY 时只一次性交给去重后的 SKU 类型，读取即删除；手围、松紧、绳材、数量、排列和价格继续使用 DIY 自己的默认值与权威规则。

### 3.7 顾客地址和优惠权益

- 顾客可维护资料、多地址及默认地址；结算选择“本单使用”不修改默认地址。地址、券加载分别显示错误和重试，不把失败伪装为空列表。
- 后台支持优惠券模板、单人、多选和全量发券。已发券冻结名称、说明、优惠金额、门槛与到期时间，模板修改或停发仅影响后续发放；撤销券是独立动作。
- 单人和批量发放必须携带批次标识；同批次相同请求返回原结果，同批次变更模板、范围或备注拒绝。全量重试不扩大原收件范围；批次、发券记录在同一事务提交。
- V19 对旧券按迁移时模板回填并标记 `MIGRATED_CURRENT_TEMPLATE`；新券为 `ISSUED_SNAPSHOT`。不将回填冒称历史发放原始规则。

### 3.8 本轮范围与验收口径

本轮按“可靠设计与运营”路线交付 R01（结算与恢复）、R02（超时关闭）、R03（冻结权益与可靠发券）、R04（指定替换与历史）、R06-A（准确轨迹）和 R20（文档/验收同步）。R05 按序制作、质检、返工及打印工单未在本轮实现；现有履约任务与 SKU 汇总 BOM 不等于完整制造工单。各项验证以 `docs/testing.md`、`docs/progress.md` 和对应 QA 记录为准，本规格不把功能落地等同于真机或生产验收通过。

## 4. 尚未实现范围

- 未接微信授权；当前使用本地安装 UUID + 顾客 JWT，换设备或清缓存后不能自动找回。
- 未接真实对象存储；当前使用本地 `FileStorage`。
- 未接微信支付、退款、发票、售后和真实物流查询。优惠券已实现，当前不包含复杂营销组合。
- 已完成有效 DeepSeek Key 的保存与 `/models` 连接测试；新版多套推荐的真实 `/chat/completions` live 验证仍待执行。
- 已实现单商品入库入口、初始库存和列表“补货”预警；主动低库存通知、真实消息发送与回执仍未实现。

## 5. 非功能需求

- JDK 17、Spring Boot 3、MySQL 8、Vue 3、原生微信小程序。
- 金额使用 `decimal`/`BigDecimal`；前端金额不作为报价权威。
- 数据库结构只通过 Flyway 演进。
- 管理接口使用管理员 JWT；小程序业务接口使用顾客 JWT，二者不能互换。
- 库存、订单、支付和履约写操作在数据库事务内完成，关键行使用行锁和前置状态条件。
- 统一响应含 `code`、`message`、`data`、`traceId`、`timestamp`。
- 默认后端端口为 8081；普通 `verify.sh` 不得访问 DeepSeek或产生外部费用，live 调用必须显式 opt-in。
- 关键流程提供 JUnit/Testcontainers、Vitest/Jest、TypeScript 检查和真实 HTTP 冒烟。
- Java 公共类型和关键规则使用中文 Javadoc；TypeScript 公共逻辑说明状态与边界。

## 6. 验收记录口径

以下为先前本地交易闭环的历史记录，不代表 2026-10-23 本轮已经重新执行全部检查。本轮准确结果以 `docs/progress.md` 与 QA 记录为准。

### 本地交易闭环 V1 历史记录

- 管理后台可维护商品、DIY 规则并处理订单履约。
- 小程序可浏览商品、完成 DIY、保存方案、填写地址、下单、模拟支付/取消并查看状态。
- 下单重新使用后端权威报价；库存不足不能创建订单。
- 下单预占、支付确认、取消释放均有库存余额和流水记录。
- 模拟支付幂等；订单和履约状态不能跳步。
- 方案和订单均按顾客身份隔离。
- `scripts/catalog-smoke.sh`、`scripts/diy-smoke.sh`、`scripts/order-smoke.sh` 已通过真实 HTTP 验证。
- `scripts/recommendation-smoke.sh` 支持暂停与显式 live 双路径；新版 live 契约会校验生日画像、后台套数、每套 3～5 种当前目录 SKU、图片和免责声明。
- 3 款图片演示散珠首次创建、第二次全部幂等跳过已经真实 HTTP 验证。
- 当前准确测试数量和新版 live 结果以 `docs/progress.md` 最新阶段记录为准。

### 完整规划范围

当前本地交易与推荐界面可用于演示和非真实收款场景。必须先由用户在后台安全输入有效 Key 并完成 live 验证；再完成微信授权、微信支付、对象存储、退款售后和生产运维清单，才具备商业上线评估条件。
